# Unlayer live AI edits

Research for [ticket #300](https://github.com/Silthus/posthog/issues/300) on [map #299](https://github.com/Silthus/posthog/issues/299). Checked October 6, 2026.

PostHog can load a replacement design and observe edits today. Unlayer documents live block mutations through its built-in AI Assistant, but PostHog disables that assistant. Its public API does not document a general block patch method, block targeting commands, a temporary read-only switch, or grouping host-applied changes into one undo step.

"Not supported" below means no supported contract was found in the public documentation or published editor API declarations. It does not prove that an internal method cannot do it. This is source research, not a browser experiment or a confirmation from Unlayer support.

## What PostHog embeds today

The research branch starts from freshly fetched upstream master, [5202af95](https://github.com/PostHog/posthog/tree/5202af95fd153f32ffc999dc1b75157e17e6362b). It passes merge tags, `displayMode: 'email'`, an action bar at the bottom, and a collapsible tools panel on the right. It sets `preview: true`, `imageEditor: true`, `stockImages: false`, and `ai: false`.
- [`emailTemplaterLogic.tsx`](https://github.com/Silthus/posthog/blob/d1e0b0f99fd58241e93a0566b1f55df2195cf880/frontend/src/scenes/hog-functions/email-templater/emailTemplaterLogic.tsx#L588) supplies project ID `275430` in Cloud or debug mode, and otherwise leaves it undefined. ## Plan and version limits

The [AI setup reference](https://docs.unlayer.com/ai/assistant/setup) requires a paid plan that includes the Assistant, a numeric `projectId`, enabled AI flags, and an identified `user.id`. PostHog currently has `ai: false` and no `user.id`. Its project ID alone does not establish that the plan includes AI. The setup docs do not state an exact minimum builder version for the Assistant or its callbacks.

[Custom JS/CSS](https://docs.unlayer.com/builder/appearance/custom-js-css) is marked as a paid feature. PostHog configures it already, but repository configuration does not prove entitlement or successful execution in every deployment. The load/save, body-values, undo, preview and template-permissions pages do not specify a paid-plan requirement or minimum version for the ordinary operations described here. Silence is not a verified plan matrix. No paid tier is documented as adding the missing general block patch, block targeting, grouped undo or read-only APIs.

The [September 25 stable release](https://docs.unlayer.com/changelog#release-2026-09-25-1ics6m1) includes Assistant changes for respecting template permissions in live mode. The published `1.501.0` types are newer than stable `1.489.0`. Their presence in PostHog's lockfile does not prove that every declared callback exists in its iframe. Pin or inspect the builder version before relying on type-only discoveries.

## The host-owned AI callback is limited

The [Assistant callback docs](https://docs.unlayer.com/ai/assistant/events-callbacks) mention `ai:assistant:generate` for host-owned generation. The [published API types](https://unpkg.com/unlayer-types@1.501.0/embed.d.ts) specify `(requestParams, done)`, with a prompt, scope, target `location`, and design data in the request. The result includes `data: object[]`, provider and model fields. The exact accepted design/block result shape remains weakly typed and is not explained by the prose docs.

The declaration explicitly says the callback delivers one final answer per turn and predates streaming. It also says `ai:assistant:on:stream` does not fire when the host owns generation. A companion `ai:assistant:abort` callback reports cancellation. The comment about a host SSE endpoint says "once available", so it does not establish a currently supported streaming endpoint configuration.

The built-in pipeline exposes request, success, error, cancel and beta stream notifications. Stream notifications include `design-operation` and `design-partial`. They observe Unlayer's own generation; they are not commands for applying PostHog's operations. There is also no documented method here to start a turn from PostHog's chat without the Assistant UI.

## Implications for live edit

Inside the iframe, the documented choices are full design loads, body-setting updates, ordinary user editing and undo, preview, and plan-gated customization. Unlayer's own Assistant can stream block edits. Its host-owned callback can return a final result, but the public contract does not support feeding PostHog's external stream of block operations into that path.

For the current PostHog AI flow, a preview layer during the turn is the evidence-backed fallback for streaming text, changed-block highlights and scroll positioning. Keep the editor mounted, show a host-controlled preview while AI works, and mask a final `loadDesign` behind it. Reveal the editor only after its load/export completes. The prototype must prove that this hides any flash; the docs do not prove it. The existing `previewHtml` callback can change preview markup, but its docs do not promise continuous preview refresh during an external AI turn.

The host must prevent editing during the turn, including keyboard focus and controls outside the iframe. An overlay alone is not proof of a complete lock. A host snapshot of the whole turn is needed to guarantee one undo across subject, preheader, body and every changed email. Keep undo in unsaved form state and restore each affected email from that snapshot. Native editor history is not documented to cover this requirement. These are prototype recommendations, not tested implementation claims.

Unresolved vendor/runtime checks: a supported external block mutation and targeting API; whether selection events are available in the loaded builder; load and mutation history behavior; the exact host-generation result schema and plan/version availability; a global runtime lock; and rendered proof of no flash. None should be assumed from internal DOM access or from the existence of Unlayer's own streaming Assistant.
